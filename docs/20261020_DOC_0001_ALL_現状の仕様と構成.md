## 2. 遊びの決まり

### カードとルール

- カード: 色（赤・青・緑）× 形（丸・三角・四角）× 数（1〜5。その形が数だけ並ぶ）＝ 45枚。番号 = 色×15 + 形×5 + (数−1)
- ルールの部品: 「色が◯」「色が◯ではない」「形が◯」「形が◯ではない」「数が k 以上（k=2〜5）」「数が k 以下（k=1〜4）」「偶数」「奇数」
- ルール: 部品1つ、または部品2つの「かつ」「または」。45枚の ○× の表が同じものは1つにまとめ、いちばん簡単な言い方を残す（全部○・全部×は除く）→ **350通り**
- 文の例: 「赤いカード」「丸ではない」「数が3以上」「赤くて丸」「赤、または数が4以上」「三角で、数が3以上」「四角で、緑ではない」「青い丸以外」

### 1問の流れ

1. 例のカードが2枚（○が1枚、×が1枚）。手がかりは「合う（○）の山」と「合わない（×）の山」に分けて並ぶ
2. 調べる（上限は★で決まる: ★1 3回・★2 4回・★3 6回）: 色・形・数を選んでカードを作り、先に「合うと思う／合わないと思う」を選んでから［調べる］。カードがめくれて答え（○×の判子）が出る。予想が外れたら「発見！」（演出・振動・効果音）
3. 調べるたびに「のこる候補」（いまの手がかりに合うルールの数）が減る（候補メーター）。候補の中身は見せない。もう分かっているカード（例・調べた・判定で分かった）は調べられない
4. いつでも［判定へ進む］。調べる回数が残っているときは、下の帯で「判定に進むと、もう調べられません」と確かめる（alert は使わない）。**判定に進んだら調べに戻れない**（判定のカードを見てから調べる、という抜け道をふさぐ）
5. 判定テスト: 5枚に ○× を答えて［答え合わせ］。全部正しければ解決。1枚でも違えば、5枚それぞれに「正しい／正しくは○（×）」を出し、その5枚は手がかり（「判」の札）に加わる。［もう一度判定］で新しい5枚（何回でも。判定の回数は記録。調べる回数は増えない）
6. 解決: ルールの公開（文と45枚の○×の一覧）、結果の★、ふり返り（候補の減り方・各回の「最悪で残る数」と最善の1枚）、調査力、ルール図鑑に登録

### 結果の★（`Engine.grade(pz, 調べた回数, 判定の回数, 調べたカード)`）

- ★3: 判定を1回で通過し、調べた回数が最善手の回数（`pz.best`）以内。または毎回が最善手と同じくらい良い1枚（最悪で残る数が最善と同じ）
- ★2: 判定を1回で通過
- ★1: 判定をやり直して解決

### 調査力

- 1回の調べで候補を何割減らせたか（(前 − 後) / 前）の平均（`Engine.review(...).power`。0〜1。画面は %）
- 調べずに判定へ進んだ問題には無い。記録帳に最近20問の推移（日替わりと練習）と平均を出す

### 難易度（問題の★）と候補の範囲

| ★ | 答えになるルール | 候補メーターが数える範囲 | 調べる上限 |
|---|---|---|---|
| ★1 | 色か形が◯（level 1） | 色と形だけのルール 21通り | 3回 |
| ★2 | 「ではない」・数の部品1つ、「ではない」を使わない「かつ」（level 2） | level 1〜2 の 99通り | 4回 |
| ★3 | それ以外の部品2つ（「ではない」を含む「かつ」・「または」。level 3） | すべて 350通り | 6回 |

- 遊び方の★の説明はエンジンの `STAR_GUIDE`（候補の範囲と上限だけ。答えの型は書かない）

### 日替わり

- No. = 2026-10-20 を No.1 とした通し番号（端末のローカル日付）。seed = `hosoku-YYYYMMDD`
- 曜日で★: 月 ★1・火 ★1・水 ★2・木 ★2・金 ★2・土 ★3・日 ★3（`Engine.WEEK`）
- 同じルールが近い日に続かない（★ごとの周回で並べる。エンジン側で保証）
- 時計が No.1 より前なら、**日付ごと** No.1 の日（2026-10-20）に丸める（番号だけ1にすると、別の日のルールが「No.1」として出るため）。ホームと記録帳に「端末の日付を確かめて」を出す

## 3. 推理エンジン（`// ==ENGINE START==`〜`// ==ENGINE END==`）

- グローバル `Engine`。DOM・window・localStorage を使わないので Web Worker でも動く。外への通信なし
- 乱数は seed から決まる mulberry32 だけ（Math.random を使わない）。生成は試す回数で打ち切る（端末の速さで問題が変わらない）
- 現在の `VERSION` は **2**（★3 の上限を 5 → 6 回にして、どの★も「最善手の同点をどれを選んでも上限の中で候補が1つになる」= sure 1）
- 作業場所で作ったエンジンを、ロジックを変えずにそのまま貼っている

### API

| 関数・値 | 役割 |
|------|------|
| `CARDS` / `RULES` | 45枚 / 350通りのルール `{id, text, op, parts, mask, size, level, cost, scope}`（簡単な順） |
| `generate({seed, star, ruleId?})` | 練習の問題（ruleId を渡すとそのルールで作る） |
| `daily('YYYY-MM-DD')` / `dailyConfig(...)` | 今日のルール（no・date・weekday つき）／問題を作らずに設定だけ（No.1 より前は no が 0 以下） |
| `test(pz, card)` | そのカードは○か |
| `candidates(pz, obs)` | 残っている候補の id（例の2枚は自動で入る。ok は使わず答えのルールで決め直す） |
| `bestQuestion(pz, obs)` | 最悪でも候補を最も減らすカード（候補が1つ以下なら `card: null`） |
| `judgeCards(pz, obs)` | 判定の5枚（まだ分からないカードから。答えと簡単さの近い候補を見抜けるカードを優先。○と×を両方入れる。同じ入力なら同じ5枚） |
| `review(pz, obs)` | ふり返り（`counts`・各回の `before/after/cut/worst/optimal/best`・`power`・`allOptimal`） |
| `grade(pz, asked, tries, obs?)` | 結果の★ |
| `tutorial(1〜3)` / `example()` | はじめての調査（`lesson` に案内の文9種）／遊び方の例（`demo` に最善手の流れ・`judge` に判定の5枚） |
| `cardText` / `ruleById` / `table` / `cardIndex` | 「赤い丸が3つ」／id からルール／45枚の ○×／カードの番号 |
| `SCOPES` / `BUDGET` / `WEEK` / `DAY1` / `STAR_GUIDE` | 候補の範囲 21・99・350／上限 {1:3,2:4,3:6}／曜日の★／'2026-10-20'／★の説明 |

- 問題（Puzzle）: `{ v, seed, star, scope, ruleId, ruleText, examples:[{card, ok:true}, {card, ok:false}], budget, best, stats:{ universe, start, path, bestCards, size, level, cost, sure, bestMax } }`
- **`ruleId`・`ruleText`・`stats.path`・`stats.bestCards` は答えにつながるので、解決するまで画面に出さない**（コピー文・読み上げ・途中の保存にも書かない）
- 公平さ: 生成時に「例の2枚のあと、最善手を続ければ上限の中で候補が1つになる（同点のどれを選んでも）」を確かめ、満たさない組は捨てる。候補が1つなら判定のどの5枚も答えが決まる
- 生成時間（Node）: ★1・★2 は 1ms 前後、★3 は平均 6ms・最大 20ms 前後

| 遊び方 | ルールとカード（色の模様の見本）・遊び方6つ・例題（Engine.example: 例の2枚 → 最善手2回 → 判定の5枚 → 「赤いカード」）・はじめての調査への入口・難しさ（STAR_GUIDE）・曜日の表（WEEK から）・連続日数・結果の★・調査力 |
| 設定 | 効果音・振動・画面の色（自動/ライト/ダーク）・記録を消す（2段階の確認。設定は残る）・通信しないことの説明・エンジン版 |

- はじめての調査: 第1話「予想して調べる」（青いカード・候補21通り・3回）、第2話「外れそうなカードを試す」（三角ではない・3回。合うカードばかり試すと候補が減らないことを体験させる）、第3話「2つの条件」（三角で、数が3以上・候補99通り・4回）。案内はエンジンの lesson（intro・make・ask・hit・miss・flat・judge・done）を場面で出し分ける。文の前提（例: 第2話の miss は「×だと思ったのに○」）に合わない場面では第1話の一般的な文を使う。解決すると次の話へ。記録（解決数・練習・図鑑・調査力）には数えない
- 練習は★ごとに途中を1件保存し、同じ★を押すと続きから。解決した問題は［次の問題］で新しい seed
- 問題は「読み込み中」を出してから次のフレームで作る
- 効果音は WebAudio でその場で作る（選ぶ・めくる・○・×・発見・判定が外れた・解決）。振動は navigator.vibrate（画面に触れる前は呼ばない）。どちらも設定で OFF
- 画面が裏に回ったら途中を保存し、音を止める。戻ったら日付を確かめ、日付が変わっていればホーム・記録帳を描き直す（1分ごとにも確かめる）。別のタブで記録が変わったらホーム・記録帳・図鑑・設定を描き直す
- 画面の行き来はブラウザの履歴にも積む（Android の戻るで前の画面へ）。調査→結果、結果→次の問題は履歴を置き換える
- コピー文（答えのルールは書かない）:
  ```
  法則ハンター No.3（★★☆）
  調べ 3回・判定 1回で解決
  候補 74→18→5→1
  連続2日
  ```
  ★は問題の難しさ。候補は例の2枚のあとから、調べるたびの数（判定で分かったカードは含めない）。練習は「法則ハンター 練習（★★☆）」で連続の行なし。コピーできない環境（Artifact の iframe など）では、選択済みの欄を出す（iframe の中では1.5秒で返事が無ければ出す）
- alert / confirm / prompt は使わない

### デザイン

- 題材は「調査ノート・標本カード」。点の方眼のノートの地、二重枠の標本ラベル（今日のルール・候補メーター・結果）、ピン、蛍光ペンの「発見」と見抜いたルール、手書きの案内。嘘つき村（和紙と判子）・段取り名人（方眼紙と付箋）とは別の見た目
- カードの絵は SVG（viewBox 60×84。数はサイコロの目の並び。数が少ないほど大きく描く）。**色は模様でも区別できる: 赤 = 塗り・青 = 斜線・緑 = 点**（`<pattern id="pt-blue">`・`<pattern id="pt-green">`）。色の組はライト `#D2412F / #2B5FC4 / #1F8A55`、ダーク `#E25B47 / #5F88EA / #2FA96B`（色覚の見分けやすさを検査済み）
- 書体（Google Fonts）: Klee One（手書き風の見出し・案内・ルールの文）、M PLUS 2（本文）、Courier Prime（番号・数字・ラベル）。Inter・Space Grotesk は使わない
- ライト/ダークは CSS のトークン（`:root` にすべて、`@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` と `:root[data-theme="dark"]` で上書き）。body に背景
- 見せ場の動き: カードがめくれて判子が押される（rotateY）、「発見！」（蛍光ペンの帯と放射線）、候補メーターの数が数え下がり帯が縮み「−n」が浮かぶ、手がかりのカードが山に飛び込む、結果の判子・ルールの蛍光ペン・★・45枚の表のマスが順に出る。`prefers-reduced-motion` ではすべて止める（発見の演出も出さない）
- 中央 480px の一列。スマホ 320〜430px で横にはみ出さない（左右16px）。下の固定バーは `env(safe-area-inset-bottom)` を足す。アイコンはすべてインライン SVG（絵文字なし）

## 5. 日付と連続日数（`// ==DAYRULES START==`〜`END`）

- 今日 = 端末のローカル日付。2026-10-20 より前なら日付ごと 2026-10-20 にする（`clampDay`・`clockBehind`）
- 日替わりを **その日のうちに解決した** ら連続 +1（★はいくつでもよい）。夜に開いたルールは翌朝3時までに解決すれば開いた日の分（`countsOnDay`）。0〜3時のホームには「昨日の No.n が調査中です」を出し、その間は連続を切らない（`pendingDay`・`shownStreak`）
- 日付が2日以内で戻っても（時差）連続を巻き戻さない。大きく戻した・進めた時計は、時計のずれとみなして数え直す（`addStreak`）
- 記録帳は全部の日付の一覧を作らず、表示する行だけ作る（`bookCount`・`bookDayAt`・`bookRows`）
- 考え方は嘘つき村・段取り名人と同じ

## 6. 保存（`// ==STORE START==`〜`END`）

localStorage のキー `hosoku.v1` に1つの JSON。

```
{ v: 1, t: 最後に保存した時刻, epoch: 記録を消した回の目印,
  settings: { sound, haptics, theme: 'auto'|'light'|'dark' },
  daily: { 'YYYY-MM-DD': { state: 'playing'|'done', obs: [カード番号…], guess: [true|false|null…], fails: [[カード番号×5]…],
                           tries: 判定の回数, judging: 判定に進んだ, grade: 0〜3, power: 0〜1|null, rule: ルールの id（解決した日だけ）,
                           v: エンジンの版, openedOnDay, solvedOnDay, streak } },
  practice: { cur: { 1: 途中|null, 2: …, 3: … }（途中 = 上の項目＋seed・star）, solved, top, byStar: {1,2,3} },
  tutorial: { done: 0〜3, dismissed, cur: { ep, …途中の項目 } | null },
  zukan: { ルールの id: { d: 初めて見抜いた日, m: 'daily'|'practice', no: 日替わりの No.|null, n: 回数 } },
  stats: { streak, bestStreak, lastDailyDate, totalSolved, top, found },
  log: [ { d, m: 'd'|'p', s: 問題の★, p: 調査力, g: 結果の★ } …最大60件 ] }
```

- 読み込みは中身の型を1件ずつ確かめる（`sanitize`）。読めない1件だけ捨て、全部は消さない。壊れた JSON は `hosoku.v1.broken` に控えて手元の記録で続ける。新しい版の保存（v が2以上）は読まず、上書きもしない
- **途中（playing）の記録には答えのルールを書かない**（`rule` は解決した記録だけ。読み込みでも途中の `rule`・`grade`・`power` は捨てる）。○×も保存せず、開き直したときにエンジンで決め直す
- ルールの id は「部品1つか、部品2つを & か | でつないだ形」（例 `red`・`!blue&even`・`circle|n>=4`）だけを図鑑のキーとして読む（`constructor` などは読まない）
- 記録を変えるときは、保存済みの最新を読み直してから自分の変更だけを重ねる（`update`。別のタブの記録を消さない）
- 「記録を消す」は設定だけ残して既定の形に戻し、`epoch` を新しい値にする。開いていた問題は開いたときの epoch を控えておき、違っていたら（別のタブで消された）途中を書き戻さない。解決は新しい記録として数える
- 版（VERSION）が変わった途中の記録は使わない（新しい問題として始める）。前の版で解決した日は、保存したルールと★だけの結果を見せる
- localStorage が使えない環境でも遊べる（「記録を保存できない環境です」と出す）
