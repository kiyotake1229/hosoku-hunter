# 点数と判定と答えの集まりの見直し

- 管理番号: #0002
- 種類: ENH（機能改善）
- 対象: ENG（推理エンジン・問題生成）。結果の画面の★・ふり返り・調査力の出し方（APP）も合わせて直した
- 作成日: 2026-10-21
- 関連: #0001（現状の仕様と構成）、#0003（点検で見つかった不具合の修正。同じ日の作業）

## 概要

点検（コードレビューと、遊んでの確認）で、「★1 の答えが6通りしかなく、例の2枚と図鑑の箱の数で答えの型が分かる」「候補が2つ以上のまま判定に進むと、判定の5枚の顔ぶれから答えが推測できる」「調べずに判定へ進んでも★3 が取れる」「調査力が判定に進んだときの残りを数えない」と指摘された。答えの集まり・判定の5枚の選び方・結果の★・調査力・日替わりの並べ方を見直し、エンジンの **VERSION を 2 → 3** に上げた。**日替わり・練習・はじめての調査・遊び方の例の問題はすべて変わる**（まだ公開前なので、遊んだ人の記録への影響はない）。

## 対象ファイル

- `index.html` — `// ==ENGINE START==`〜`// ==ENGINE END==`（エンジン）、結果の画面の文（`gradeMsg`・`reviewHTML`・`powerHTML`）
- `tools/check-engine.mjs` — エンジンの検査（新しい決まりの検算・回帰ハッシュ VERSION 3・わざとバグを入れた写し）

## 変更内容

### 1. 答えの集まり = 候補メーターの範囲

| ★ | これまで（VERSION 2）の答え | これから（VERSION 3）の答え | 候補メーター |
|---|---|---|---|
| ★1 | 色か形が◯（level 1）の6通り | 色と形だけのルール 21通り（◯・◯ではない・◯くて◯） | 21通り |
| ★2 | level 2 の93通り | level 1〜2 の99通り | 99通り |
| ★3 | level 3 の251通り | すべて 350通り | 350通り |

- メーターの数 ＝ 本当にありうる答えの数になった（`Engine._internal.POOL[★]` が範囲と同じであることを検査）。「★1 なら答えは色か形が◯」「図鑑の★1 の箱は6つ」のような読みができなくなった
- 公平さ（例の2枚のあと、最善手の同点をどれを選んでも上限の回数の中で候補が1つになる＝sure 1）は、★ごとに答えの集まりの全部のルール（21＋99＋350＝470通り）で、指定して問題が作れることを確かめた。外したルールは無い（`UNFAIR` は空のまま）
- `Engine.generate({ seed, star, ruleId })` は、★を star のままにする（ルールがその★の範囲に無ければ、入るいちばん小さい★）。これまでは★をルールの level にしていた
- 図鑑の標本箱も範囲ごと（★1 の範囲21・★2 で増える78・★3 で増える251）に分けた（#0003）

### 2. 判定の5枚の選び方

- **候補が2つ以上**: 答えのルールを使わず、残っている候補と、まだ分からないカードだけで選ぶ（`judgeOpen`）。どの候補が答えでも、同じ5枚・同じ順になる。1枚ずつ、次の順で良いものを選ぶ
  1. 候補どうしで答えが割れるカード（割れるカードが5枚以上あれば5枚とも割れるカード）
  2. 見分けられる候補のまとまり（5枚の○×の並びが違う組）が多い
  3. ○と×の両方が入る候補が多い（「○と×を両方入れる」を、答えではなく候補の上で考える）
  4. 割れ方が半々に近い → 5. 色・形・数がまだ出ていない → 6. seed と手がかりで決まる順
- **候補が1つ**: これまでどおり、答えの境目のカードで、○と×の両方を入れる（`judgeOne`。答えはもう見えている手がかりで1つに決まっているので、答えを使っても漏れない）
- 判定をやり直すときの新しい5枚も同じ（外れた5枚の答えが手がかりに加わった候補で選び直す）
- 点検の再現スクリプト（作業場所の `qa-code/t3_judge_fingerprint.mjs`）で、日替わり365日・最善手の途中で候補が2つ以上残る場面のうち、5枚の組を見れば答えが1つに決まる場面は **直す前 1,203場面中 1,195（99.3%）→ 直したあと 1,195場面中 0**。候補が2つの場面で「○×の釣り合いが良いほうが答え」と当てる読み（`t3b_judge_human.mjs`）は **当たり 598・外れ 79 → 743場面すべて同点**（どちらの候補でも5枚の○×の数が同じ）

### 3. 結果の★（`Engine.grade(pz, obs, tries)`）

| 結果 | 決まり |
|---|---|
| ★3 | 判定に進んだ時点で候補が1つ・判定を1回で通過・調べた回数が最善の範囲（この答えで最善手を続けたときの回数 `best` 以下か、毎回が最善手と同じくらい良い1枚） |
| ★2 | 判定を1回で通過（候補が2つ以上のまま判定に進んで当てたときは最高でも★2。調べずに判定へ進んで当てても★2） |
| ★1 | 判定をやり直して解決 |

- 引数を `grade(pz, 調べた回数, 判定の回数, 調べたカード)` から `grade(pz, 調べたカード, 判定の回数)` に変えた（判定に進んだ時点の候補の数を数えるため）
- 結果の文も合わせた（#0003）: 調べずに通過したときは「調べずに判定へ進み、1回で通過。候補はまだ N通りあった」。「見事な調査」は★3 のときだけ

### 4. 調査力とふり返り（`Engine.review(pz, obs)`）

- 調査力（`power`）＝ 1回の調べで候補を減らせた割合の平均。**判定に進んだ時点で候補が2つ以上残っていたら、「減らせなかった1回」（0）を1回分足して平均する**（調べずに判定へ進むと 0）
- `bestPower` を足した: この問題を最善手で解いたときの調査力。結果の画面で「今回 X%／この問題の最善なら Y%」と並べる
- 各回に `other`（逆の答えだったら残った候補の数）と `lucky`（最善の1枚の「最悪で残る数」より少なく残った＝運よく減った）を足した。ふり返りで「運よく減った（逆の答えなら N通り残った）」と添える
- ふり返りの「最善手を続けると N回」は「この答えなら N回」と書き、「最悪で残る数は、答えが分からないうちの見込み」と添えた（点検の「最悪で残る2 なのに1回で絞れる」の食い違い）。「最悪の場合の回数」も試したが、答えの集まりを広げたことで上限を超える答えがある（公平さは本当の答えについて保証している）ため、出さないことにした

### 5. 日替わりの並べ方

- 答えの集まりが★ごとに入れ子（21 ⊂ 99 ⊂ 350）になったので、★の周回だけで並べると、★をまたいで同じルールが近い日に出る（例: 月曜の★1 と土曜の★3 が同じ「赤いカード」）
- 週（月曜はじまり）ごとに7日分を決めるようにした
  - ルールを2つの組に分ける（どの★でも同じ組。範囲ごとに seed で並べて交互に）。偶数の週は組0、奇数の週は組1 のルールだけを使う → となりの週とは同じルールが出ない
  - 同じ週の中は ★1（月火）→ ★2（水木金）→ ★3（土日）の順に決め、その週にもう出たルールを避ける（当たったら同じ周の半分先から順に）
  - ★と組ごとに、組のルールを seed で並べた周を順に使う（周の頭に前の周の最後の1/3を置かない）
- 同じルールは7日以内に出ない（7日以内の2日は同じ週か、となりの週）。どの日付も1週分の計算で決まる（9999-12-31 でも軽い）。3年分で★をまたいだ最短の間隔は★1 8日・★2 12日・★3 16日
- 「答えの型が★で決まらない」ことも検査する（3年分で、★1 の日に「◯ではない」「◯くて◯」、★2 の日に色と形だけのルール、★3 の日に範囲1〜3 のルールが出る）

### 6. はじめての調査と遊び方の例

| | VERSION 2 | VERSION 3 | 日替わりで初めて出る日 |
|---|---|---|---|
| 第1話 | 青いカード | 赤いカード（例: 赤い丸2つ○・青い丸2つ×） | No.43 |
| 第2話 | 三角ではない（★2） | 四角ではない（★1。例: 赤い丸2つ○・赤い四角2つ×。2-4-6 の形は同じ） | No.105 |
| 第3話 | 三角で、数が3以上 | 同じ | No.206 |
| 遊び方の例 | 赤いカード（**No.1 の答えと同じだった**） | 四角のカード（例: 赤い四角3つ○・赤い丸3つ×） | No.47 |

- はじめての調査・遊び方の例のルールは、日替わりの最初の4週（No.1〜28）に出ない（検査で確かめる）
- 案内の文（lesson）に `first`（初めて調べる前。第2話は「候補が減らなかった」を体験するまで、×のカードを勧めない）と `out`（調べる回数を使い切ったとき）を足し、`judge` を「候補が1つに絞れた」ときの文にした（「回数0」なのに「外れそうなカードで確かめてから判定へ」と出る食い違いを直した）。第1話の「上の2枚」を「下の『合う』『合わない』の山にある例の2枚」に直した

### 7. 検査（`tools/check-engine.mjs`）

- 足した・変えた項目: 答えの集まり＝範囲（21・99・350）／★ごとに答えの集まりの全部のルールで公平な問題が作れる（470通り）／判定: 候補が2つ以上なら答えが候補のどれでも同じ5枚（候補を入れ替えて 29,574 回）・割れるカードを優先・検算（エンジンとは別に書いた選び方）と一致・候補が1つなら○と×の両方／結果の★（調べずに通過・候補2つ以上で通過は★2）／ふり返り（other・lucky・判定に進んだときの残りを数えた調査力・bestPower）の検算／日替わり: ★をまたいでも7日以内に同じルールが出ない・答えの型が★で決まらない／はじめての調査・例のルールが最初の4週に出ない／GOLDEN に VERSION 3
- わざとバグを入れた写し（`--mutants`）を、新しい決まりに合わせて作り直した（判定を答えで選ぶ・割れるカードを優先しない・答えの○×で並べる・答えの集まりを level に戻す・判定に進んだ時点の候補を見ない★・調査力で残りを数えない・運よく減ったの比べ方・週の組・同じ週の重なりなど）

## 確認

- `node tools/check-engine.mjs index.html` → **PASS 95項目**（約12秒）。回帰ハッシュ（VERSION 3）: daily365 `e043f2e67a941e45f9e95fbe9872ccd7` / practice120 `df36876bfe3f9c5786d6fd3c2b359d0e` / fixed4 `7b992706172291017b92af57f07ef9e3`
- `node tools/check-engine.mjs index.html --mutants` → 25種の写しすべてで、狙った検査項目が FAIL（下の「確認の記録」）。写し1本ごとに60分で打ち切る（生成が止まらなくなる写しで、検査全体が終わらなくならないように）
- 生成時間（Node）: 平均 2.5〜3.9ms・最大 57〜77ms（★3 の答えの集まりが広がったぶん少し増えた。上限 50ms／300ms の内）
- 注意: パソコンがほかの処理でとても重いとき・途中で一時停止したときは、「性能」の項目が時間で FAIL することがある（作業中に一度、1問の生成が15分と測られた）。そのときは `--no-perf` で中身だけ確かめ、空いているときに測り直す
- 点検の再現スクリプト（直す前 → 直したあと）
  - 判定の5枚の組で答えが決まる場面（候補が2つ以上）: 99.3% → 0%（上の2）
  - 調べずに判定へ進んで通過したときの★（`qa-web/notes/grade0.mjs`）: ★3 → ★2
  - ★1 の答えの型（`qa-code/t2_level_leak.mjs`）: 答えが level 1 の6通りに限られなくなった（★1 の日替わりで「◯ではない」「◯くて◯」も出る）
- 画面での確かめ（Chrome の画面なしモード）は #0003 に書いた。候補が2つ（四角のカード／赤くて四角）の場面で判定に進み、答えを入れ替えても5枚が同じことを、画面とエンジンの両方で確かめた
