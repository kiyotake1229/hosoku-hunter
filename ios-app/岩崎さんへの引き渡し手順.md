# 岩崎さんへ — 「法則ハンター」iOSアプリ ビルド・申請手順

岩崎さん

毎日1問の仮説検証パズル「法則ハンター」の iOS プロジェクトです。
色・形・数のカードに隠れた「ルール」を、自分でカードを作って試しながら見抜くパズルです（例: 「赤くて四角」のカードだけが合う、など）。
**Xcode で開いてビルド → App Store 申請** まで進められる状態にしてあります。

1. Xcode で開き、署名（Team）を自社アカウントに設定してビルド → 3章・4章

申請時に入力するアプリ名・説明文・キーワードなどは、6章に**下書きを用意してあります**。
そのまま使っていただいても、修正いただいても構いません。

**申請の前に、清武が決めてお知らせすること**（決まるまでは申請を止めてください）:

- 岩崎さんの Mac の macOS で、どの Xcode を使うか（2章の表。macOS 27 の Mac なら、清武が先に対応します）
- 審査のガイドライン 1.5 のための、問い合わせ用のメールアドレス（6章「サポート URL」）。いまのサポートページの連絡先は GitHub の Issues だけです
- 5章の「EU の取引業者（trader）の申告」と「App Review の連絡先」に入れる会社の情報・担当者（嘘つき村の事件簿・段取り名人で済ませていれば、同じアカウントでは申告は1回だけです）

ご不明な点があればお知らせください。（清武）

## 1. アプリ概要

| 項目 | 内容 |
|------|------|
| アプリ名 | 法則ハンター（ホーム画面の表示も「法則ハンター」） |
| Bundle ID | `work.ltv.hosoku` |
| 構成 | Capacitor 7（Web アプリ `../index.html` を同梱したネイティブアプリ。WebView で外部サイトを表示するものではない） |
| 対応端末 | iPhone（iOS 14 以上）・縦向きのみ。iPad では iPhone 用の画面で動く |
| 通信の有無 | **遊ぶのに通信は不要**（機内モードでも全機能が動く）。表示用の書体（Google Fonts）だけ、ネットにつながっているときに読み込む。記録や操作の内容を送ることは無い |
| データ保存先 | **端末内のみ**（WebView の保存領域＋ネイティブの Preferences に二重に保存）。外部送信・収集なし |
| ネイティブ機能 | ローカル通知（毎朝「今日のルールが届きました」。時刻を選べる。通知の文に答えは書かない）、触覚フィードバック（色・形・数を選ぶ・調べた結果が出る・予想が外れた「発見」・判定の外れ・解決）、状態バーの文字色をアプリの画面の色に合わせる、記録の二重保存 |
| 広告・課金・アカウント | なし |

### 遊び方（審査・動作確認用）

- 隠れたルール（例: 「赤くて四角」「数が3以上」「青い丸以外」）が、どのカードが「合う（○）」かを決めている。最初に例のカードが2枚（○1枚・×1枚）見えている
- 色（赤・青・緑）・形（丸・三角・四角）・数（1〜5）を選んでカードを作り、「合うと思う／合わないと思う」を選んでから［調べる］。カードがめくれて ○× が出る。予想が外れたら「発見！」
- 調べるたびに「のこる候補」（いまの手がかりに合うルールの数）が減る。調べられる回数は★で決まる（★1 3回・★2 4回・★3 6回）
- ルールが分かったら［判定へ進む］→ 5枚のカードに ○× で答えて［答え合わせ］。全部正しければ解決。外れても［もう一度判定］で新しい5枚に何度でも挑める
- 解決すると、ルールの文・45枚すべての ○×・ふり返り（最善の1枚とのくらべ）・調査力が出て、ルール図鑑に登録される
- 毎日1問の「今日のルール」（全員同じ問題）は曜日で難しさが変わる（月・火 ★1、水〜金 ★2、土・日 ★3）。練習（★1〜★3）は何問でも遊べる。過去の日は「記録帳」から遊べる
- 初めて開くと、ホームに「はじめての調査」が出る。［第1話を始める］で案内つきの3問（各1〜2分。記録には数えない）。審査で遊び方を見せたいときはここから
- 問題はすべてアプリの中でその場で作り、いちばん良い調べ方なら上限の回数のうちに答えが1つに決まることを確かめてから出している

## 3. ビルド手順

ターミナルで、このフォルダ（Dropbox の `アプリ開発/思考力/法則ハンター/ios-app`）に移動して、以下を順に実行してください。
（`cd ` と打ってから、Finder でこのフォルダをターミナルにドラッグすると場所が入ります）

```bash
# 0) 日本語のパスで CocoaPods が止まらないように（ターミナルを開くたびに1回）
export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8

# 1) 依存パッケージを取得（初回のみ。数十秒）
npm install

# 2) アプリ本体（../index.html）を iOS 側へ反映し、pod install まで行う
npm run sync

# 3) Xcode で開く
open ios/App/App.xcworkspace
```

> **注意**: 必ず `App.xcworkspace` を開いてください（`App.xcodeproj` ではありません）。
> 手順2で `✔ Updating iOS native dependencies with pod install` と出れば成功です。
> この Mac（清武の作業用）には Xcode が無いため、ビルドの確認は GitHub のクラウド Mac（GitHub Actions の「iOS build check」）で行っています。

### `npm run sync` でエラーが出たら

| 表示されるエラー | 対処 |
|---|---|
| `pod: command not found` | `brew install cocoapods` を実行してから、もう一度 `npm run sync` |
| `Unicode Normalization not appropriate for ASCII-8BIT` | 手順0の `export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` を実行してから、もう一度 |
| `xcodebuild requires Xcode, but active developer directory ... CommandLineTools` | Xcode を一度起動して初期設定を済ませ、`sudo xcode-select -s /Applications/Xcode.app` を実行してから、もう一度（Xcode 26 の名前を変えて置いた場合は、その名前の .app を指定） |
| `CocoaPods could not find compatible versions` | `cd ios/App && pod repo update && pod install && cd ../..` を実行 |
| `npm ERR!` で始まるもの | `rm -rf node_modules && npm install` をやり直す |

それでも通らない場合は清武までご連絡ください。エラー文をそのまま貼っていただければ対応します。

### 動作確認

上部のデバイス選択から実機またはシミュレータ（iPhone）を選び ▶ で起動します。確認ポイント:

- 起動画面にアプリのアイコン（夜の調査ノートに標本カード2枚と黄色い虫眼鏡）が出て、ホーム（今日のルールのカード）に切り替わる。端末がダークのときは起動画面の地も暗い色になる
- 初めて開くとホームに「はじめての調査」が出る。［第1話を始める］で第1話が開き、カードを作ると下の帯に案内が出る
- ホームの［調査を始める］→ 色・形・数を押すと軽く震える → 「合うと思う」か「合わないと思う」を選んで［調べる］→ カードがめくれて ○× が出て、震える。予想と違うと「発見！」が出て強めに震える（振動は実機のみ）
- 調べるたびに「のこる候補」の数が減る。［判定へ進む］（調べる回数が残っていると、下の帯で確かめる）→ 判定テストの5枚に ○× を付けて［答え合わせ］。1枚でも違うと震えて［もう一度判定］が出る。全部正しければ「解決」（震える）で、結果の画面にルール・45枚の ○×・ふり返り・調査力が出る
- 設定 →「毎朝の通知」を ON にすると通知の許可を求められる。許可すると「知らせる時刻」が選べる（その時刻に「今日のルールが届きました」が届く。本文は「No.◯（難しさ★…・候補◯通り）」で、答えは書かない。通知を押すと今日のルールが開く）
- 設定の「画面の色」を「ダーク」「ライト」に切り替えると、画面上端の時計・電池の文字色もそれに合わせて変わる（端末の外観と逆にしても読める）
- 調べている途中でホームボタン（ホームへのスワイプ）でアプリを裏に回し、戻っても途中から続けられる
- アプリを完全に終了して開き直しても、解決の記録・連続日数・ルール図鑑が残っている
- 機内モードでも起動して遊べる（書体だけ端末の書体になる）
- 設定のいちばん下の「サポート・プライバシーポリシー」で、サポートページ（GitHub Pages）が開く

5. Capability の追加は不要です（**Push Notifications は入れない**。このアプリの通知は端末内で予約するローカル通知なので、プッシュ通知の設定は要りません）

## 5. App Store 申請の手順

**最初の申請の前に1回だけ（アカウント単位）: EU の「取引業者（trader）」の申告**

App Store Connect の **「ビジネス」→ 契約 → コンプライアンス → Digital Services Act** で、trader status（取引業者かどうか）を申告します。嘘つき村の事件簿・段取り名人の申請で同じアカウントで済ませていれば、もう一度行う必要はありません。

- **EU で配信しない場合でも申告が必要**です。まだ申告していなければ、提出のときに求められます
- 会社として出すなら「trader（取引業者）」を選びます。D-U-N-S に登録した住所と、ここで入力した電話番号・メールアドレスが、EU 27か国の App Store の製品ページに表示されます
- メールと電話に届く確認コードの入力と、会社名・住所を証明する書類（登記簿謄本など）の提出が要ります。確認に数日かかることがあるので、早めに済ませてください
- 住所などを EU のストアに出したくない場合も申告は必要で、その場合は配信国から EU の国々を外すことになります

1. [App Store Connect](https://appstoreconnect.apple.com) →「アプリ」→「＋」→「新規アプリ」
   - プラットフォーム: iOS / 名前: 6章のアプリ名 / プライマリ言語: 日本語 / バンドルID: `work.ltv.hosoku` / SKU: `hosoku-001`（任意の文字列）
2. Xcode: 上部のデバイスを **Any iOS Device (arm64)** にして **Product → Archive**
3. Organizer が開いたら **Distribute App → App Store Connect** でアップロード（10〜30分ほどで App Store Connect に出てくる）
4. App Store Connect でアプリ情報を入力（6章の下書き・スクリーンショット・プライバシー・年齢制限）
5.「App Review に関する情報」
   - **連絡先（必須）**: 氏名・メールアドレス・電話番号を入れる。審査で質問があったときに Apple が連絡する先で、利用者には表示されません。電話番号は +81 から始まる国際形式（例: `+81 90-1234-5678`）。岩崎さん、または窓口の担当者を入れてください
   - メモ欄に7章の英文を貼る（サインインは不要なので「サインインが必要」はオフ）
6. 価格は「無料」、配信国を選び（EU の国を含めるなら、上の trader の申告が済んでいること）、ビルドを選んで **審査へ提出**

## 7. 審査で見られやすい点

Apple のガイドライン **4.2（最低限の機能）**: WebView でサイトを表示しただけのアプリはリジェクトされます。本アプリは次の点で満たしています。申請時の備考欄（App Review に関する情報 → メモ）に英文を貼ってください。

- 完全オフラインで動く自立したアプリ。問題はアプリ内の推理エンジンが端末の中で自動で作る（サーバーから問題を取ってくることはない）。いちばん良い調べ方なら上限の回数のうちに答えが1つに決まることを確かめてから出す
- 端末内にデータを保存し、毎日続けて使う設計（日替わりの記録・連続日数・練習の途中・はじめての調査の進み具合・記録帳・ルール図鑑・調査力の推移）。保存は WebView とネイティブの Preferences の二重

備考欄の記入例:
```
Hosoku Hunter (Rule Hunter) is a daily hypothesis-testing puzzle game. A hidden rule decides which cards "fit" (for example "red and square"). The player builds a card by choosing a color, a shape and a number, predicts whether it fits, tests it, narrows down the remaining candidate rules, and finally names the rule by passing a five-card judgement test.

- Works fully offline. Every puzzle is generated on the device by the reasoning engine bundled in the app, which confirms before showing the puzzle that the best questioning strategy always identifies the rule within the allowed number of tests. No server is used and no remote website is displayed. The only network request is optional loading of web fonts (Google Fonts); without a connection the app uses system fonts.
```

## 8. アプリ内容を修正したい場合

アプリ本体は1つ上のフォルダの `index.html` です（画面・推理エンジン・絵まですべてこの1ファイル）。修正後、このフォルダで:

```bash
export LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8
npm run sync
```

を実行すると iOS プロジェクトに反映されます。そのあと Xcode で Build 番号を1つ上げて、再ビルド → Archive → アップロードしてください。

- 推理エンジン（`index.html` の `// ==ENGINE START==`〜`// ==ENGINE END==`）を変えたときは、先に `node ../tools/check-engine.mjs ../index.html` を実行し、最後に `PASS` が出ることを確かめる。画面・保存・ネイティブ連携を変えたときは `node ../tools/check-app.mjs ../index.html`（画面の操作を変えたときは `node ../tools/check-ui.mjs ../index.html` も。Google Chrome が要る）
- エンジンの問題の作り方を変えると、全員の日替わりの問題が変わります（エンジンの `VERSION` を上げる決まり。`../.claude/rules/documentation.md`）
- アイコンを変えるとき: `../icon.svg` を直して `python3 ../tools/make-images.py icons`（アイコンと起動画面の元を作り直す）→ このフォルダで `npm run icons`
- `www/` と `ios/App/App/public/` は `npm run sync` が作るコピーです。ここを直接直しても次の sync で消えます
- 作業が終わったら `rm -rf node_modules ios/App/Pods` で消してください（Dropbox の同期が重くなるため。次は `npm install` → `npm run sync` で戻ります）
- GitHub（`kiyotake1229/hosoku-hunter`）に push すると、GitHub Actions の「iOS build check」が、シミュレータ向けと実機向け（署名なし）のビルドが通るかを確かめます
